# `kairo --help` audit

Audit of every flag printed by `kairo --help` (Stage 1, debug build of 2026-10-14) against what the compiler actually does. Each flag was run through `--print-clang-args`, `--print-ld-args` and a real compile, then traced from `Compiler/Command/FlagRegistry.k` through `Compiler/Config/*.k` to whatever reads the resulting field (or nothing). Per-flag raw reports are in `private/help-audit/out/`.

Base invocation used throughout (the `--target` needed an `=`; the glued spelling is rejected, see below):

```
kairo --resource-dir=build/llvm/lib/clang/22 --builtins-dir=Lib/builtin --std-dir=Lib/std \
      --cache-dir=/tmp/kcache --target=x86_64-linux-musl test.k
```

## Totals

| | count |
|---|---|

| - [x] (bound and consumed, observable effect) | 124 |
| accept-and-ignore (bound into Config, nothing reads the field) | 187 |
| stubs (consumer exists but prints "not implemented" / TODO) | 2 (`--dump-type-info`, `--print-macros`) |
| registered but never read from args | 0 user-facing (`print-ast` looked unbound to a grep; it is bound via `_mode_or`) |
| help text judged inaccurate or over-promising | ~230 (mostly the - [ ] flags) |
| lit tests landed in `Tests/CLI/` | 91, all passing; see "Tests" at the bottom |

Three in five flags do nothing. They parse, they validate (sometimes), they are stored, and no pass, backend or linker ever looks at them. None of them warns.

## The two flags you asked about

**`--print-clang-args`** is accurate. It prints the exact cc1 argv, compiles nothing, exits 0, quotes words the shell would split. Covered by `Tests/Driver/print_clang_args.k`. One wart: `--print-cg` / `--print-ir` still dump their output under it, because codegen runs to build the line.

**`--print-ld-args`** has four problems:
- Says "kld invocation". It prints `ld.lld ...` (or `ld64.lld` / `lld-link` per flavor).
- Says "does not link" and implies "and exit" like the other `--print-*`. It runs the full compile first (`/tmp/kcache/test.o` is rewritten), then prints the link line instead of linking. If the compile fails, you get diagnostics and no line. Side effect: it is an argument to consider it a `-###` style flag, not an info query.
- The line shows `-o a.out`. The default output is `a.out`, not `<input>` basename.
- On a windows-msvc `--target` the line mixes lld-link args with ELF/musl ones (`-m elf_x86_64`, musl crt files). Unverified beyond one observation.

## Real bugs found (not just help text)

1. **Value flag swallows the next flag, then can abort.** `--xray -o out`, `--stats-file -o out`, `--time-trace -o out`, `--panic-handler`, `--edition`, `--profile-use`, `--wasm-export`, `--incremental-dir`, `--module-name` ... any String flag given without a value takes `-o` as its value, then parses the old output path as a source file. If that path exists (a previous binary) the compiler aborts with the `SymbolTable.k:217` "append after freeze" assertion, exit 134. If it does not exist you get `fatal [I005F]: no such file` and, oddly, exit 0. Reproduced at orchestrator level. The U004E "requires a value" path only fires when the flag is last on the line.
2. **`--cmax-errors=0` drops every error.** Help says 0 = unlimited. Actual: only `I957E too many errors` is printed and exit is 0, so a broken program "compiles". Cause: `CompilerInstance.k:1949` passes 0 to `set_error_limit` and `Engine.k:801` compares `>= limit`. Confirmed.
3. **`--cmax-scope-depth` 1..8 hangs the compiler** (timeout, no output) even on `fn main(){}` with `--type-check-only`. Registry minimum is 1. Confirmed: `--cmax-scope-depth=4` times out at 10s, `=12` exits 0.
4. **`-DNAME=VALUE` (the form `--help` shows) does not define NAME.** `Command.k` ~650-675 parses `-DFOO=7` as long flag `DFOO`, splits to `D`+`FOO`, then `=7` overwrites the value, so the define pushed is `7`. Only `--define=FOO[=V]` / `-D=FOO` work. `-D` also only reaches the Kairo preprocessor, never clang. Source-traced by the agent; my own `--dump-preprocessed` check was inconclusive because `#if` is not evaluated in that dump.
5. **`--print-cpus --target=bogus` and `--print-target-info --target=bogus` exit 1 with no output.** P004F is built but `flush_errors()` is never called (`CompilerInstance.k:792`, `:879`), unlike `print_dirs` / `print_clang_args`.
6. **`--print-pass-pipeline` is in `wants_info_query` but has no branch in `run_info_query`** (`CompilerInstance.k:527`): prints nothing, exits 0, and skips the compile entirely.
7. **`--m32` is half-applied.** Picks the i686 sysroot and `usize` width but leaves cc1 `-triple x86_64`, so every compile dies with `CL001E` size_t typedef mismatch.
8. **`-W <code>` is - [ ] for native diagnostics.** `warn_list` is never passed to `set_policy`; only `-A`/`-E`/`-F` are. `-W` still maps `C*` codes to clang `-W<group>`. Also: all four take diagnostic *codes*, not names, and `_diag_code_to_number` keeps only digits, so `SC005`, `S005` and `5` collide. `-A` silences errors too.
9. **`-c -o x.o` / `-S -o x.s` / `--emit=asm -o x` fail for any normal program** with `I004F "-o names one output, but this build emits N"` because the builtin and std modules count as outputs. Help says "with -c the one object". Only `--no-prelude` single-TU builds work.
10. **`--emit`** accepts only `obj|asm|llvm-ir|llvm-bc`; help lists `tokens|ast|sema|bcir|cxx|dep-info` which all error "not implemented yet". The error's list and the help's list disagree.
11. **`--no-prelude` / `--prelude <file>` and `--force-include <file>`:** the file is parsed and checked but its declarations are not visible to the main TU (`R020E`), contrary to the help and to the source comment "as if `import <file>::*`".
12. **`--cmax-tuple-arity=0`** rejects every tuple; help says 0 = unlimited. `--cmax-union-width` help says 0 = unlimited; registry range is 2..65536. `--cmax-macro-expansions` same (min 1).
13. **`--cxx-std=c++17`** is advertised but every compile fails (`Lib/builtin/types.k` needs `__builtin_coro_*`, R020E). `c++20`/`c++23` work.
14. **`--no-fp`, `--no-unsafe`, `-fno-unsafe`, `--no-ffi`, `--no-cxx`, `-fno-implicit-conv`**: the "hard error" promises are all unimplemented except `-fno-implicit-conv`, which works but breaks `Lib/builtin/fmt.k` (SC063E) so it is unusable with the prelude.
15. **`--save-temps`** keeps only `.o` under `<out>.kobj/`, and only when `--cache-dir` is unset. No `.ll`/`.bc`/`.s`. Help lists all four.
16. **`--build-id=`** (empty) silently drops `--build-id`; help says default `fast`.
17. **`--shared` / `--dll`** fail on the default musl target with `L001E sysroot is static-only`; the help says nothing. `--dll` is an unconditional alias of `--shared` on every platform, not Windows-only.
18. **Cache writes are not atomic.** Concurrent invocations sharing `--cache-dir` occasionally see `L001E /tmp/kcache/builtin/*.o: unknown file type` and a 0-byte `fmt-*.o.tmp`. Seen by five agents running in parallel; not a flag bug, noted because the user said parallel runs were safe. Also seen once: `--target=aarch64-unknown-linux-gnu` linking x86 builtin objects from the cache, which may be the same race or the cache not being keyed by triple.

## Help text that lies (live flags)

- `--explain` example `E0042` is not a valid code; real codes look like `R049E`. Codes must be zero-padded as printed.
- `--print-targets` says "target triples" but prints LLVM arch names (`x86-64`, `aarch64`), which `--target` rejects.
- `--print-cfg` says "all active --cfg flags"; it echoes only the user's `--cfg` strings, and `--cfg` itself gates nothing (bound-dead for conditional compilation).
- `--print-dirs` says "all include/lib search paths"; it is a toolchain/sysroot report, one lib dir, no include dirs, and user `-I` dirs are not listed.
- `-I/--include` says "module/header search path"; it is module-only and never reaches clang.
- `--macro-search-path` says "dedicated ... macro-only"; it calls the same `_add_root` as `-I`.
- `--ffi-include` and `--cxx-include` are byte-identical in effect (both push `-I dir` to clang).
- `--no-stdlib` says "include or link"; it only drops the `std` import root, link line unchanged.
- `--freestanding` says it implies `--no-stdlib --no-crt --no-prelude`; it also implies `--no-default-libs` and adds `-e main`, and a trivial program then fails to link (`malloc` from the always-linked `kairo/fmt.o`).
- `--no-crt`: the resulting binary segfaults (exit 139) because `-e main` with no CRT.
- `--entry` only matters when no CRT is linked; otherwise silently ignored.
- `--builtins-dir` has an undocumented side effect: its parent becomes the runtime root and the clang `-I` changes. Nonexistent builtins/std/resource dirs are never diagnosed directly.
- `--sysroot` is silently ignored for any `--target` with a bundled sysroot (help does say this, but a nonexistent sysroot is never diagnosed; it surfaces as `CL001E 'coroutine' not found`).
- `--resource-dir` does far more than "builtin headers": it feeds `-resource-dir`, `-isystem`, `-internal-isystem` and is the fallback root for `builtin`, `std` and the runtime.
- `-c` says "sugar for --emit obj". `--emit=obj` is the default and links; `-c` means do not link.
- `-E` is `--error <code>`, not preprocess. A stale comment in `Config/Frontend.k:32` says otherwise.
- `-O 2` (space) is a bare `-O` = `-O1`, no error. `-O=2` and `--opt 2` give `-O2`.
- `--dwarf-version` only acts with `-g`; `--debug-macros`, `--embed-source` likewise need `-g` and are silently ignored without it. `--embed-source` with DWARF < 5 gives a raw clang error.
- `--mcpu` adds a second `-target-cpu` after the default one.
- `--Wall/--Wextra/--Wpedantic` only forward to clang; no Kairo diagnostic is gated by them. `--Wextra` and `--Wpedantic` spray warnings from `Lib/builtin` on every program.
- `-fpie` only affects the link line (static-PIE on musl); objects are never compiled PIC. `-fpic` does nothing; only `--pic-level N` sets `-mrelocation-model pic`.
- `-feh-frame-hdr` is ELF-only and on by default; only `-fno-` changes anything. `-fgc-sections` help says `--gc-sections`; actual token is per flavor (`-dead_strip`, `-opt:ref`).
- `-frelro` gives partial RELRO (`-z relro`); full needs `--now`, not mentioned.
- `--hash-style`, `--dynamic-linker` are silently ignored for static links, which is the default musl target. `--rpath` is emitted even for `-static`.
- `--export-dynamic` says "pass -E"; token emitted is `--export-dynamic`.
- `--linker-script`, `--version-script`, `--ld-flags` say "kld"; it is `ld.lld`. `--linker-script` is rejected on Mach-O with L001E.
- `--strip` beats `--strip-debug` when both given; not stated.
- `--rtlib=libgcc` works; `--unwindlib` is silently ignored whenever the sysroot has a manifest (all bundled ones). "platform default" is really libgcc-if-rtlib-is-libgcc-else-libunwind.
- `--icf-mode` is only validated when `--icf` is also present.
- `--threads` also sets lld `--threads=N`; help says only "multi-file compilation".
- `-v/--verbose` prints only the ld line and a generic INFO trace, not "every clang invocation".
- `--macro-debug` and `--macro-debug-filter` print nothing unless `-v` is also given.
- `--print-sema`, `--print-lowered` say "dump IR"; they dump Sema declarations (5k+ lines incl. builtin/std). `--print-cg` says "after optimization passes"; it is the codegen token stream. `--print-ir` "CXX IR" is the generated C++ text. All three dump every TU including Lib.
- `--print-ast` "(default: tree)" is misleading: bare `--print-ast` errors or swallows the next arg; only `--print-ast=` gives tree.
- `--print-imports` also prints an undocumented overlay section.
- `--emit-headers=<unwritable>` exits 0 silently; also skipped when sema had errors.
- `--time-trace` to an unwritable path exits 0 with only a message.
- `--error-format` honours only `basic`; `json|msvc|pretty|bogus` all give pretty. Overlaps `--cerror-format` / `--fdiagnostics-format` which advertise a different value set.
- `--no-color` could not be verified without a tty.
- `--cmax-macro-depth` is also the parser's `unwrap_expansion` cap: a low value on a tail-position macro chain prints ~20 `I002F`+`S063N` pairs then `I957E` instead of one `R008E`.
- `--cmax-token-count` error is per file, with no location or file name, and counts builtin/std files.
- `--cmax-import-depth` works (R019E). `--cmax-file-size-mb` works (S066E).
- `--version` prints the host triple regardless of `--target` (probably intended).
- `--targetx86_64-linux-musl` (glued, no `=`) is `U002E unknown flag`. Noting because the pasted base command had it.

## Duplicates and aliases

- `--ffi-include` == `--cxx-include` (same `-I` push to clang, `CompilerInstance.k:1089-1090`).
- `--macro-search-path` == `-I` (`CompilerInstance.k:1124-1125`).
- `--dll` == `--shared` on every platform.
- `--no-exceptions` vs `-f[no-]exceptions`; `--no-unsafe` vs `-f[no-]unsafe`; `--no-overflow` vs `-f[no-]overflow-checks` vs `--unsigned-trap` ("extends --no-overflow", which does nothing). All dead.
- `--remap-path-prefix` subsumes `--debug-prefix-map` and `--coverage-prefix-map` by its own description; `--no-timestamps` == `--source-date-epoch=0`. All dead.
- `-fpic` vs `--pic-level` (only the latter works). `--ld-flags` vs `--Xlinker`; `--cxx-flags` vs `--Xcxx`.
- `--error-format` vs `--cerror-format` vs `--fdiagnostics-format` (different advertised value sets).
- `--no-prelude` and `--no-builtins` produce the same resolution failure; `--no-prelude` additionally drops the builtin objects from the link.
- `--emit=obj` is the default; `-c` is the real "object only".
- **Undocumented spellings that work:** `--opt N`, `-O=N`, `-g0` (single dash), `-Idir`, `--include=dir`, `-mcpu=`.
- **Registered but not in `--help` and rejected on the CLI:** `--no-omit-fp`, `--stack-prot`, `-fsanitize=` (a `sanitize` StringList with alias `fsanitize` exists at `FlagRegistry.k:540`; `-fsanitize=address` gives "unknown flag, did you mean -fsanitize-ub"), `-finline` (registered twice, shown once).
- **Dead duplicate Config bindings** (same flag read into two Config structs, one copy never read): `static`/`shared`/`no-entry`/`save-temps`/`dll`/`entry` in `Config/Frontend.k` (linker copy wins); `strip`/`strip-debug`/`icf`/`icf-mode`/`rtlib`/`f_pie` in `Config/CodeGen.k` (linker copy wins); `lib-dirs`/`link-libs` in `Config/Invocation.k`; `no_prelude`/`no_stdlib`/`no_default_libs`/`no_crt` in `Config/Language.k`.
- **Stale test-only registry:** `register_test_flags` (`FlagRegistry.k:477-570`) re-defines ~25 names (`help`, `version`, `explain`, `output`, `target`, `opt`, `profile`, `quiet`, `sysroot`, `resource-dir`, `prelude`, `no-prelude`, `no-stdlib`, `wall`, `wextra`, `werror`, `nowarn`, `unsafe`, `dead-code-elim`, `tail-call`, `inline`, `max-errors`, `max-warnings`, `max-inline-depth`, `no-omit-fp`, `stack-prot`, `sanitize`...) with different help text, defaults and ranges (`max-errors` 50 vs registry 413; `max-inline-depth` range 1-64). Not user-visible, but it is why grep finds "duplicates".
- Not a duplicate: `-f` appears 50 times in `--help` only because every feature is rendered `-f[no-]X`. The registry has no duplicate name, short, long or help string.

## Cross-cutting parser and help-renderer issues

- **"(default: X) (default: X)"** on 29 lines: the description already embeds the default and the renderer appends it again. Affected: `--input-encoding --entry --cxx-std --cxx-abi --lto --dwarf-version --coverage-format --error-format --diag-cascade --diag-show-context --incremental-dir --module-cache-dir --build-id --hash-style --compress-debug --subsystem --wasm-initial-memory --wasm-stack-size --wasi-version --pic-level --test-format --test-exit-code --fp-model --fp-contract --thread-model --unwind-tables --xray --icf-mode --wasm-exec-model`. `-O` has "-O0 (default)" plus "(default: 0)". `--cmax-tuple-arity` has "default = 128 ... (default: 128)".
- **Flag name rendered as `'-'`** in U003E/U004E for every flag without a short alias: `flag '-' value 7 is out of range [0, 2]`, `flag '-' / '--sysroot' requires a value`, and `'-' / '--'` for `--c*` cfg flags. `Command.k:804`.
- **Bool flags accept `=anything`** and treat it as true (`--shared=false` enables; `--strip=bogus` ok). No `--no-X` form exists for default-true bools. **Feature flags accept `=bogus`.**
- **Enumerated String flags are mostly unvalidated**: `--borrow-check`, `--amt-mode`, `--lto`, `--profile`, `--edition`, `--coverage-format`, `--fp-model`, `--fp-contract`, `--thread-model`, `--subsystem`, `--rpath-origin`, `--wasi-version`, `--wasm-exec-model`, `--xray`, `--hash-style`, `--emulation`, `--compress-debug`, `--build-id`, `--cxx-std`, `--error-format`, `--test-format`, `--unwind-tables`, `--icf-mode` (without `--icf`) all take `bogus` with exit 0. The ones that reach lld/clang fail there with L001E or a raw clang error.
- **I32 overflow** (`--heap-size=99999999999`) reports "expects an integer", not out of range.
- **Info-query flags are first-match-wins** (help > version > explain > print-targets > print-cpus > print-target-info > print-dirs > print-clang-args > print-cfg); the rest are silently dropped.
- **Unknown-flag suggestion** can suggest the flag it just rejected ("did you mean '--include'").
- Two agents reported "space form `--flag value` rejected". That was the fish single-argument artifact; I re-ran `--pic-level 1` as two args and it works. Space form is fine everywhere tested except `-O 2` (above) and `-D FOO`.

## Tests

`Tests/CLI/` is new. Each file pins one flag's correct, deterministic behaviour via `%kairo`, mostly through `--print-clang-args` / `--print-ld-args`; ld-line tests use `--target=x86_64-linux-musl` with `REQUIRES: bundled-sysroot`. Nothing in `Tests/CLI/` asserts a behaviour listed above as a bug. Existing coverage not duplicated: `Tests/Driver/{print_clang_args,explain_code,bundled_sysroot}.k`, `Tests/Sema/Types/typeres_alias_depth.k`, `Tests/Sema/Pattern/unmatched_flag.k`.
